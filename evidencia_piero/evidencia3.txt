# Plan de validación y casos de prueba

*Sistema:* SIGD — DocuCore  
*Componente:* gestión de tipos de documento y formularios dinámicos  
*Versión:* 1.0  
*Base funcional:* el solicitante elige un tipo de documento, completa su formulario y el sistema crea el expediente en estado BORRADOR.

## 1. Objetivo

Comprobar que DocuCore permita configurar formularios por tipo de documento y capturar respuestas válidas, sin mezclar campos, expedientes ni configuraciones. Este plan no cubre requisitos, adjuntos ni radicación final.

## 2. Criterios de entrada y salida

*Entrada:* existe un administrador, un solicitante y un tipo de documento activo con formulario configurado.

*Salida satisfactoria:* todos los casos críticos aprobados; no se persisten códigos duplicados, campos fuera de su formulario, respuestas duplicadas ni valores incompatibles con la configuración.

## 3. Reglas que se validan

| Código | Regla de negocio | Capa recomendada |
|---|---|---|
| RN-FOR-01 | El código de tipo de documento es obligatorio y único. | Base de datos y backend |
| RN-FOR-02 | Un tipo de documento tiene un único formulario. | Base de datos |
| RN-FOR-03 | El nombre y el orden de un campo son únicos dentro de su formulario. | Base de datos |
| RN-FOR-04 | Solo los campos de selección tienen una lista de opciones. | Base de datos y backend |
| RN-FOR-05 | Los campos obligatorios deben estar completos antes de enviar. | Interfaz y backend |
| RN-FOR-06 | La respuesta debe coincidir con el tipo definido del campo. | Interfaz, backend y base de datos |
| RN-FOR-07 | Un expediente solo responde campos de su propio formulario. | Base de datos |
| RN-FOR-08 | Hay una única respuesta por campo en cada expediente. | Base de datos |
| RN-FOR-09 | Todo expediente nuevo nace como BORRADOR, sin código ni fecha de radicación. | Base de datos |

## 4. Datos de prueba

| Elemento | Valor |
|---|---|
| Administrador | admin@sigD.pe |
| Solicitante | solicitante@sigD.pe |
| Tipo de documento | SOL-001 — Solicitud general |
| Campo 1 | asunto, TEXTO, obligatorio, orden 1 |
| Campo 2 | cantidad_copias, NUMERO, obligatorio, orden 2 |
| Campo 3 | fecha_solicitud, FECHA, obligatorio, orden 3 |
| Campo 4 | tipo_persona, SELECCION, obligatorio, orden 4; valores: NATURAL, JURIDICA |
| Campo 5 | observacion, TEXTO, opcional, orden 5 |

## 5. Casos de prueba

| ID | Prioridad | Acción / dato | Resultado esperado |
|---|---|---|---|
| CPF-01 | Alta | Crear SOL-001 con nombre “Solicitud general”. | Se registra el tipo de documento. |
| CPF-02 | Alta | Crear otro tipo con código SOL-001. | Rechazo por código duplicado; RN-FOR-01. |
| CPF-03 | Media | Crear un tipo con código o nombre vacío. | Rechazo por dato obligatorio; RN-FOR-01. |
| CPF-04 | Alta | Crear el formulario v1 para SOL-001. | Se registra el formulario. |
| CPF-05 | Alta | Crear un segundo formulario para SOL-001. | Rechazo; RN-FOR-02. |
| CPF-06 | Alta | Registrar asunto con orden 1 y luego otro campo con orden 1. | Se rechaza el segundo campo; RN-FOR-03. |
| CPF-07 | Media | Crear tipo_persona como SELECCION sin opciones. | Rechazo; RN-FOR-04. |
| CPF-08 | Media | Crear observacion como TEXTO con opciones. | Rechazo; RN-FOR-04. |
| CPF-09 | Alta | Crear un expediente para SOL-001. | Nace en BORRADOR, sin código oficial ni fecha de radicación; RN-FOR-09. |
| CPF-10 | Alta | Crear un borrador con código EXP-2026-0001. | Rechazo; RN-FOR-09. |
| CPF-11 | Alta | Responder los campos obligatorios con: “Pedido de certificado”, 2, 2026-08-29, NATURAL. | Se guardan las cuatro respuestas. |
| CPF-12 | Alta | Intentar enviar sin asunto. | Bloqueo y mensaje: “Asunto es obligatorio”; RN-FOR-05. |
| CPF-13 | Alta | Guardar dos en cantidad_copias. | Rechazo por formato numérico; RN-FOR-06. |
| CPF-14 | Alta | Guardar 29/08/2026 como fecha. | Rechazo: se exige AAAA-MM-DD; RN-FOR-06. |
| CPF-15 | Media | Guardar EXTRANJERO en tipo_persona. | Rechazo: opción no configurada; RN-FOR-06. |
| CPF-16 | Media | No completar observacion. | Operación permitida: el campo es opcional. |
| CPF-17 | Alta | Insertar una segunda respuesta para asunto del mismo expediente. | Rechazo por respuesta duplicada; RN-FOR-08. |
| CPF-18 | Alta | Usar en el expediente de SOL-001 un campo que pertenece a otro formulario. | Rechazo; RN-FOR-07. |
| CPF-19 | Media | Desactivar SOL-001 e intentar iniciar un expediente nuevo. | El trámite no aparece disponible y no se crea expediente. |
| CPF-20 | Media | Desactivar el formulario y abrir el trámite. | El sistema bloquea la captura e informa que el formulario no está disponible. |

## 6. Evidencia a registrar

Por cada ejecución guardar: identificador del caso, fecha, responsable, datos usados, resultado real, evidencia (captura o registro del sistema) y estado APROBADO / FALLIDO.

## 7. Resultado esperado de la prueba integral

El solicitante puede crear una solicitud con datos válidos y obtener un expediente en BORRADOR. Si falta un campo obligatorio o un valor tiene formato incorrecto, el sistema lo informa antes de continuar y no guarda datos inconsistentes.
