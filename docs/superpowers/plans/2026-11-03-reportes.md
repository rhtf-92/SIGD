# Reportes y tableros SIGD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Make Reportes a usable, accessible, responsive, data-backed analytics and export module on `F_BARTRA`.

**Architecture:** Keep the existing React page, TanStack Query hook, chart components, and MGD analytics backend. Align requests and response DTOs to handlers actually mounted by this branch; add only the missing read/export capability needed by assigned behavior. Keep calculations in typed pure functions and present empty/error states without fabricated success data.

**Tech Stack:** React 19, TypeScript 5.9, TanStack Query, Express, PostgreSQL, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-03-reportes-design.md`

## Global Constraints

- Work only in the existing `F_BARTRA` checkout; preserve its pre-existing dirty files.
- Use live `F_BARTRA` backend routes and document differences from the M06 guide.
- MGD indicators: VTEP, TPR, TRO, TEO; denominator guards; business hours exclude weekends/holidays per existing service.
- Text contrast at least 4.5:1; keyboard operation and accessible semantics.
- No silent mock/demo data on API failure.

## Review Focus

- MGD zero denominator/empty period: assert finite neutral KPI values.
- Date range/month boundary and query parameters: assert exact requests and prevent out-of-range trend points.
- Partial endpoint failure: assert visible retryable error, never fabricated metrics.
- Spanish names and accents in exports: assert UTF-8 content and filenames.
- Keyboard-only chart/filter/export use: assert focusable controls and accessible names.
